## Shape-encoder validation reuses the first five training objects

Status: Implementation issue · Checked: 2026-09-26

The public VQ-VAE entry point builds train and val from the same dataset root. The loader builds the same eligible model list for both and truncates non-training splits to its first five entries. Validation IoU is then used to select the best checkpoint.

### Reviewed material

RoomDesigner commit 3980e06bfc48f76f3f1efb2d2182c0c871d2231b: 3DILG/run_vqvae.py, datasets.py and FRONT.py.

### Observed evidence

The public VQ-VAE entry point builds train and val from the same dataset root. The loader builds the same eligible model list for both and truncates non-training splits to its first five entries. Validation IoU is then used to select the best checkpoint.

### Reason for flagging

The validation objects are a prefix of the training object list, not a disjoint object split. Resampling surface and occupancy points on these objects does not create validation on unseen object identities. The checkpoint selection consequently measures reconstruction on objects already included in training.

### Scope and author response

This is the public shape-encoder training path, separate from the room-level scene-generation test split and its reported FID/SCA results.
