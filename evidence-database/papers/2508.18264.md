## README and paper report inconsistent performance metrics

Status: Reporting discrepancy · Checked: 2026-09-26

The pinned README claims 87.7% F1 with four tokens, while arXiv v2 Table 21 reports 74.84 F1. The abstract’s performance-retention percentage also differs from the table-derived ratio. The final OpenReview PDF was not obtained; the finding is limited to these versions.

### Reviewed material

MMTok README at commit 8e2686836ed5bbe05d064f1d1c20e50c73c70b94; arXiv 2508.18264v2 abstract and Table 21.

### Observed evidence

The README describes 87.7% F1 with four visual tokens. Table 21 instead reports 74.84 F1 for the four-token POPE setting and 85.9 for the full model. Their ratio is approximately 87.12%. The abstract describes 87.7% as retained performance rather than absolute F1.

### Reason for flagging

Absolute F1 and a percentage of retained baseline performance are different quantities. The linked descriptions cannot be reconciled as the same reported setting without a metric or version explanation.

### Scope and author response

The final OpenReview PDF was not obtained. The finding concerns the pinned README and arXiv v2, not every paper version. It establishes inconsistent reporting, not fabricated measurements.

## Padding exclusion can exhaust valid tokens and repeatedly select a masked token

Status: Implementation issue · Checked: 2026-09-26

The selector caps its token budget by the total token count, without subtracting excluded padding tokens. When valid candidates run out, the remaining iterations take argmax over all-negative-infinity scores and repeatedly select index 0.

### Reviewed material

MMTok commit 8e2686836ed5bbe05d064f1d1c20e50c73c70b94; LLaVA-1.5 tensor-input path with padding exclusion, finite coverage scores and a requested budget exceeding eligible candidates.

### Observed evidence

The selector caps its token budget by the total token count, without subtracting excluded padding tokens. When valid candidates run out, the remaining iterations take argmax over all-negative-infinity scores and repeatedly select index 0.

### Reason for flagging

For a 1008-by-336 image, the published padding rule excludes eight rows at the top and eight at the bottom of a 24-by-24 grid, leaving 192 eligible tokens. With the README budget of 256 and padding exclusion enabled, the first 192 iterations consume all eligible tokens; the next 64 select masked index 0. The output is neither padding-free nor a subset of 256 distinct tokens.

### Scope and author response

The result follows from the padding arithmetic and loop control flow. The frequency of this input condition in the paper benchmarks was not measured.
